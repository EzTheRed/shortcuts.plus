# Shortcuts Plus Website API

Cloudflare Worker base URL: `https://api.shortcuts.plus`

## Endpoints

### 1. Get a webpage

`POST /get-website`

Send JSON `{ "url": "https://example.com" }` with a valid Basic token in the
`Authorization` header. A successful response contains only the finished,
packaged HTML file, with these headers:

```http
Content-Type: text/html; charset=utf-8
Content-Disposition: attachment; filename="webpage.html"
```

The response body is HTML, starting with the packaged document, rather than a
JSON dictionary. Authentication and validation errors still return JSON with an
`error` property and an appropriate HTTP error status.

**Migration from the former JSON response:** remove **Get Dictionary from
Input** and extraction of `file` from existing shortcuts. Use the response
itself as the HTML file. The API no longer returns `file`, `dynamic`, `metadata`,
or `instructions` fields. It does not extract links or forms into native menu
definitions, and it does not preload linked pages.

### 2. Generate a vCard menu file

`POST /vcf-menu`

Send the JSON object directly as the POST request body. Each property name
becomes a contact title, and its string value becomes the subtitle:

```json
{
  "title": "description",
  "Item 1": "An item.",
  "Item 2": "Another item."
}
```

For Apple Shortcuts, use **Get Contents of URL** with method **POST**, set the
request body to **JSON**, and include the API's Basic token in the
`Authorization` header. No URL encoding or query parameter is needed. Returns
one downloadable `shortcuts-menu.vcf` file containing one separate vCard
contact per object property, in the same order.

### 3. Ask the AI

`POST /ai`

Send `Content-Type: application/json`, a fresh Basic token issued for `ai`, and
a JSON object containing only `prompt`:

```json
{
  "prompt": "What does https://shortcuts.plus do?"
}
```

The prompt must contain 1–250 Unicode code points after trimming surrounding
whitespace. The entire request body is limited to 4,096 bytes. Additional fields,
including model overrides or conversation history, are rejected.

A successful response uses `Content-Type: application/json; charset=utf-8` and
contains a top-level array of 1–16 answer parts in reading order. Every part
contains exactly two string fields, `type` and `contents`, with no wrapper or
additional fields. For example:

```json
[
  {
    "type": "text",
    "contents": "Shortcuts.plus is an Apple Shortcuts-oriented website with a shortcut library and APIs that extend what the Shortcuts app can do."
  }
]
```

`type` identifies the content category. This text-only endpoint emits only
`"text"` parts. `contents` is a nonempty string, preserving line
breaks and the order of the answer. Programming, language, and HTML examples
remain text within `contents`. Image and audio parts are not generated by this
endpoint; category-based handling can support them if separate capabilities are
added later.

The AI handles general questions, language, programming, and jokes. It has
supplied context describing shortcuts.plus as an Apple Shortcuts website with a
shortcut library and APIs, but does not browse URLs, read files, or retain
conversation history. Answers are not cached.

Inference uses Cloudflare's native Workers AI binding with
[`@cf/google/gemma-4-26b-a4b-it`](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/),
reasoning disabled and a fixed `max_completion_tokens` of 512. Clients cannot
change the model or generation settings. Native `response_format` constrains
generation with a JSON schema allowing only `type: "text"`, and the server
validates the result before returning it. Malformed, truncated, or invalid model
results return `503`; inference is not retried automatically and there is no
fallback model.

Successful responses are arrays. Errors instead return a JSON object with an
`error` property and an appropriate HTTP status:

| Status | Meaning |
| --- | --- |
| `400` | Invalid JSON, invalid prompt, or unsupported request fields. |
| `401` | Missing, invalid, expired, already-used, or wrong-API Basic token. |
| `413` | Request body exceeds 4,096 bytes. |
| `415` | Request does not use `application/json`. |
| `429` | Workers AI quota or capacity limit; includes `Retry-After`. |
| `503` | AI binding or inference is unavailable, or the generated result is malformed, truncated, or invalid. |

A valid token is consumed before the AI request is validated, including when
validation or inference returns an error. Obtain a new token for every attempt.

### AI budget and availability

The $0 setup requires the **Workers Free** plan. The existing Worker and D1
authentication database are reused, with no paid fallback, account upgrade, or
AI Gateway credits. According to
[Cloudflare's Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/),
the free allocation is **10,000 neurons per account per day**, shared by all
callers and other Workers AI usage in the account. It resets at **00:00 UTC**.
On Workers Free, requests fail after the allocation is exhausted; they do not
incur AI overage charges. Workers and D1 retain their own free-plan limits.
Public tokens allow anyone to consume the shared allocation, so availability
depends on total usage. A future move to Workers Paid would enable billable
usage above the free AI allocation and would no longer preserve this $0 setup.

## Authentication

The public `POST /auth` endpoint issues a short-lived, single-use Basic
authorization value. It does not require Cloudflare Access or an identity login.

Send JSON containing only `api` (`get-website`, `vcf-menu`, or `ai`). The response body
is only the Basic authorization value as plain text. Tokens expire after 10
seconds, are bound to the selected API's ID, and can be used once.

Example request:

```json
{
  "api": "get-website"
}
```

Each protected API has its own fixed ID. The Basic authorization username
contains that API ID, and the API verifies that the ID matches its own before
consuming the token. A token issued for one API cannot authorize another API.
No caller-provided name is requested or used.

Because `/auth` is public, anyone can request a token. Keep issued authorization
values private and use them immediately.

## Suggested Apple Shortcuts flows

### Ask the AI

1. Add **Ask for Input**, set the input type to **Text**, and save its result as
   the prompt. Keep the prompt within 250 Unicode code points.
2. Add **Get Contents of URL** for `https://api.shortcuts.plus/auth`, set the
   method to **POST**, and set the request body to **JSON** with the text field
   `api` set to `ai`. Save the returned plain-text Basic authorization value.
3. Immediately add **Get Contents of URL** for `https://api.shortcuts.plus/ai`,
   set the method to **POST**, and set the request body to **JSON** with the text
   field `prompt` set to the result of **Ask for Input**. Set the `Authorization`
   header to the complete value returned by `/auth`, including its `Basic `
   prefix. The JSON body setting supplies `Content-Type: application/json`.
4. Add **Repeat with Each** using the response list. Within the repeat, use
   **Get Dictionary Value** on **Repeat Item** to get `contents`.
5. Pass `contents` to **Show Result**, keeping the repeat order. The top-level
   response is already a list, so it does not need **Get Dictionary from Input**;
   each **Repeat Item** is a dictionary. You can also read `type` for category
   branching if future endpoints add media; this endpoint always returns `text`.

Collect the prompt before requesting authorization: the token expires after
10 seconds and can be used only once. A retry needs a new token.

### Package a webpage

1. Call `POST https://api.shortcuts.plus/auth` with JSON
   `{ "api": "get-website" }` and retain the plain-text Basic authorization value.
2. Request `https://api.shortcuts.plus/get-website` using **Get Contents of URL**
   with method **POST** and JSON body `{ "url": "https://example.com" }`. Set the
   HTTP `Authorization` header to the value returned by `/auth`.
3. Use the response directly as `webpage.html` and pass it to **Quick Look**.
   If Shortcuts treats the response as text, name or save it with an `.html`
   extension before previewing it.

Quick Look displays the HTML file. The Worker does not provide native
interaction menus or callbacks from the preview. To package another URL, obtain
a fresh token and repeat the request with that URL.

## Packaging behavior

The Worker packages only the requested page and its linked CSS/JavaScript
resources. It inlines linked stylesheets, nested CSS imports (limited depth),
and external script files, rewrites CSS URLs to absolute URLs, and injects a
base URL so remaining relative resources can resolve. Packaged pages are
cached briefly for repeat requests; links and form targets are not fetched in
the background.

When the requested page is the Shortcuts Plus homepage
(`https://shortcuts.plus/`), the API returns a dedicated static collection with
an Apple-inspired layout. It fetches `/data/shortcuts.json` and includes every
valid catalog entry, with its title, description, categories, and destination
link. ID-based entries resolve their current name, description, and download
URL through the same registry as the website
(`POST https://s.shortcuts.plus/`). Production calls use the `REGISTRY` service
binding to `shortcuts-registry`, because Cloudflare does not support ordinary
fetches between same-zone routed Workers. Legacy HTTPS links remain supported. If a
lookup fails or returns an unsafe link, the entry still appears with a link to
its detail page. The collection is not limited to 60 shortcuts and does not
require JavaScript execution in Quick Look.

For YouTube pages containing supported public embedded video data, the Worker
returns a static feed with the detected videos, thumbnails, and available
video details. Other pages use the regular HTML packager.

The Worker does not execute JavaScript or render the page in Chromium. Some
sites require cookies, authentication, anti-bot challenges, or browser execution
and may not work in the packaged file.

The Worker accepts only public HTTP/HTTPS destinations,
blocks local/private/reserved hosts, validates redirects, and does not forward
user cookies or credentials. HTML is limited to 2 MB; each fetched CSS/JS
resource to 1 MB; aggregate CSS/JS to 4 MB; and no more than 24 external CSS/JS
resources are fetched. Images, fonts, video, and other binary media remain
external.

## Active API directory

`GET https://api.shortcuts.plus/api` returns a plain-text, single-array list of
every active endpoint, including its HTTP method:

- `POST /auth` — issue a short-lived token for an active API.
- `POST /get-website` — return a packaged HTML file for a public webpage.
- `POST /vcf-menu` — generate a vCard menu file.
- `POST /ai` — answer a text prompt of up to 250 Unicode code points.

The former Posts API has been retired. No publishing, listing, or
individual-post endpoints are active.

## Test and deployment

Run `npm test` in `get-website` for the AI and catalog request-handler regression
tests. Tests use mocked AI inference, registry, authentication storage, and
cache; they do not call production services or consume the AI allocation.

Deploy both the website and the `shortcuts-get-website` Worker to release the
matching views. Preserve the Worker's existing production bindings and settings,
including `AUTH_DB`, `REGISTRY`, and its existing secret bindings, when deploying.
The AI endpoint also requires the native Workers AI binding named `AI`.
